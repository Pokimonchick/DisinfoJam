# Сохранения — памятка для разработки

## Что работает

- Один слот кампании. Новая история просит имя и предупреждает о замене слота.
- «Продолжить» возвращает на сохранённую страницу пролога, обучения или сюжетного эпизода, в смену или домой. После завершения финального эпизода кнопка открывает итог.
- Автосохранение после действий, каждые 5 секунд во время игры, при паузе, уходе в меню, потере фокуса и обычном закрытии окна. При аварийном завершении может потеряться время после последнего сохранения.
- Восстанавливаются шкалы, деньги, время, очередь материалов, выбранный заголовок, ещё не закрытый результат публикации, комбо, кофе и покупки дома. Результат повторно не начисляется.
- Сохраняется признак уже полученных дополнительных секунд за лояльность. Загрузка посреди смены не начисляет этот бонус повторно; в старых сохранениях без нового поля действует значение по умолчанию.
- Анимации не сохраняются. Если закрыть игру во время засыпания, загрузка вернёт домой перед сном; 10 выносливости восстановятся только после завершения сна.
- Пролог знакомит с героиней главы «Амнезия». Имя выбирается для её представления в редакции. Сюжетные эпизоды перед второй и четвёртой сменами не расходуют рабочее время; просмотренные страницы и завершённые эпизоды сохраняются в `presentation.story`.

## Цель кампании

Открой `Data/mvp_balance.tres` в инспекторе → **Цель кампании**:

| Параметр | Начальное значение |
| --- | --- |
| Campaign Days | 5 смен |

Проверка происходит в конце последней смены **после аренды**. Если персонаж выжил, первая глава завершена независимо от накопленной суммы. Обычные поражения имеют приоритет. Затем показываются архивная находка и итоги недели. Длина кампании фиксируется при начале новой истории; изменение ресурса влияет на следующие прохождения.

Поле `campaign_money` сохранено для совместимости со старым форматом, но больше не влияет на завершение главы. Старый финал `goal_missed` при загрузке становится завершённой главой. Старое сохранение посреди смены продолжает её без вставки уже пропущенного утреннего эпизода.

## Где лежит сохранение

`user://saves/campaign.json`, рядом `campaign.json.bak` — предыдущая исправная копия.
На Windows обычно: `%APPDATA%/Godot/app_userdata/DisinfoJam/saves/`.

Игра сначала пишет временный файл, затем заменяет основной. При повреждении основного пробует резервный и сообщает об этом. Формат из более новой версии игры не загружается молча как старый.

## Как добавить новую механику

Обычным сценам интерфейса ничего подключать не нужно: сохраняются данные, а не дерево узлов.
Если механика содержит новый прогресс, дай ей постоянный ID и зарегистрируй отдельный раздел:

```gdscript
var purchased: Array = []

func _ready() -> void:
    GameState.register_save_section("room_upgrades", capture_save, restore_save)

func capture_save() -> Dictionary:
    return {"purchased": purchased.duplicate()}

func restore_save(data: Dictionary) -> void:
    purchased = data.get("purchased", []).duplicate()

func _exit_tree() -> void:
    GameState.unregister_save_section("room_upgrades")

# После покупки или другого значимого действия:
# GameState.request_save()
```

Возвращай полный снимок своего раздела: словари, массивы, строки, числа и bool. Не сохраняй Node, Resource, Callable или пути к узлам. При отсутствии раздела обработчик получает `{}` и должен восстановить начальные значения. Если сцена появляется позже, она получит данные при регистрации. Разделы отсутствующих сцен сохраняются. У каждого раздела должен быть один владелец.

Для нового поля самой `NewsroomSession`: добавь значение по умолчанию в `reset()` и поле в `NewsroomSaveData.NUMBERS` / `FLAGS`, а при необходимости — проверку допустимых значений. Старые файлы без этого поля получат значение по умолчанию.

## Изменение формата и будущие режимы

- `SaveRepository` отвечает за JSON, замену файла, резервную копию и версии. `NewsroomSaveData` — за данные текущей игры. `mvp_game.gd` — за автосохранение и восстановление экрана.
- Корневой `format_version` сейчас равен 1. Добавление необязательного поля с дефолтом не требует смены версии. При несовместимом изменении увеличь `FORMAT_VERSION` и зарегистрируй миграцию `N → N+1` в `save_store.migrations` **до загрузки**. Не меняй смысл существующих ключей без миграции.
- Неизвестные поля основных разделов сохраняются при повторной записи. Зарегистрированная механика сама отвечает за совместимость своего раздела; можно хранить в нём собственную версию.
- Профиль содержит постоянный `id`, имя и `endless_unlocked`. Победа сохраняет флаг разблокировки. Прохождение содержит отдельный `run.id` и `mode = "campaign"`.
- Бесконечный режим, таблица рекордов и сеть пока не реализованы. Будущий переход должен продолжать текущий профиль и файл, не вызывать `_new_run()`.
- Сохраняются полные тексты источников и варианты с эффектами, а также `NewsArticle.provenance`. Будущая генерация сможет добавлять материалы в очередь: после загрузки не потребуется повторный запрос к модели. Для неограниченной игры отдельно потребуется ограничить рост архива/очереди. API-ключи в сохранение класть не нужно.

Проверки: `Tests/save_tests.gd` проверяет сохранения и восстановление; `Tests/mvp_tests.gd` — игровой цикл. Оба используют отдельные временные слоты, не сохранение игрока.
